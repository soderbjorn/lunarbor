Lunarbor Orbit

A 3D way into the vault. Every node has its own place in space and its own page there. You write on the page in front of you exactly as you do today, and you fly only when you zoom. Step back and the same tree becomes a map, with links running as pipes between branches and your windows floating beside the nodes they show.

This is the flat editor, the same one Lunarbor has today. Edit a title or press Enter for a new bullet: the dimmed space behind you updates as you type. Click a bright dot to move this window into that node.

The one rule

Find things in space. Write on flat glass.

Text in perspective is hard to read and even harder to edit. So the 3D view is for getting your bearings, finding things and arranging your workspace. When you start writing, the window docks flat in front of you at its true pixel size, and it is the normal Lunarbor editor with all its keys. The space stays behind it, dimmed, and changes as you type. Press Escape and you are back in space, exactly where you were.

Pages: every node has a place

Each node with children has a fixed spot in space, and its page hangs there. The page in front of you is the zoomed node, shown at its true pixel size with its whole nested outline, and it is a normal Lunarbor editor. The pages of its child nodes hang behind it, to the left and right. A thread runs from each bullet's dot to its page, so you can see where a dot leads before you click it.

Editing never moves the camera. Enter, Tab, Shift-Tab, Backspace and folding all happen on the page in front of you. When an indent gives a bullet its first child, that bullet gets a page of its own: a new page sprouts in the space behind you, and you go there only if you want to.

Only navigation flies. Clicking a dot or pressing ⌥⏎ zooms in, which means a flight into that bullet's page. Esc flies back out, and Back / Forward, breadcrumbs, tab switches and clicks on a page behind you are flights too. Your keystrokes go to the new page from the moment the flight starts, so typing never waits for the animation.

Why this works for Lunarbor:

  • It is the vault's own shape. On disk, each node is a folder with one _node.md. Here each node is a place with one page.
  • It changes the view, not the model. The camera follows the pane's zoomedLineId and file. The page is the window's MainScreen, and zoomInto, zoomOut and navigateToLink are what start flights.
  • Zooming into a leaf works as it does today. The leaf gets an empty placeholder child, which you can see as a new page. If you leave it empty, the placeholder is removed and the page goes with it.
  • Each window is its own view into the space. A tab's windows sit side by side in its usual split layout, and each one flies on its own: zooming in one window leaves the others where they are. A page open in two windows is the same page, so typing in one shows up in the other as you type.
  • The workspace stays as it is. Tabs still switch sets of windows. "+ Window" still splits the focused window, and closing one gives its space to a neighbour. Each page's header shows which windows are on it.
Inspiration

What to take from Lunamux, and what to change

Lunamux has two 3D features. The 3D mode puts real terminal panes on a sphere using CSS3D: a tab's panes fan out sideways and the tabs sit on a vertical wheel. The 3D tab overview draws snapshots of the panes in WebGL, in one of seven switcher layouts. Lunamux places windows on fixed rings. Lunarbor has a second structure to show, the tree itself, so the windows have to sit somewhere in it.

Keep

Real DOM panes, never textures

Lunamux moves the live xterm elements onto CSS3D planes, so they keep working. Lunarbor's windows should be real MainScreen panes too, never pictures of them. Then a docked window is the editor, with no copy to keep in sync.

Keep

1:1 front window

Lunamux places the camera so the front pane has exactly one screen pixel per CSS pixel, and caret placement and text selection stay exact. Docking a Lunarbor window does the same.

Keep

Navigate, then engage

Lunamux has two modes. Arrow keys move around the world until Enter "engages" a pane, and then keys go to the pane. Here, arrow keys walk the tree and E or a click docks a window for writing.

Keep

State you can see

Lunamux panes glow while an agent works and pulse amber while one waits for input. In Lunarbor the same signals mark unsaved edits, outside changes, MCP agent activity and broken links.

Change

Windows stay near their nodes

A Lunarbor window is not placed on a ring. It floats next to the node it shows, joined to it by a line. When the window moves to another node, its line moves with it, so the workspace always tells you where things are.

Change

WebGL for the tree, DOM for the words

A vault can have thousands of nodes, which is too many for CSS3D planes. The bodies, branches and pipes are drawn in WebGL. Labels and windows are DOM layers placed over the canvas, so text stays crisp.

The vault as a place

Every Lunarbor concept gets a shape

The 3D view adds nothing to the data model. It only shows what the vault already contains. A rule of thumb: if something has no 3D shape, it doesn't appear in space, and you still reach it from a docked window.

Layouts

Three shapes for one tree

Each shape answers a different question, so the user switches with L and the bodies move to their new places. All three are deterministic: positions come from folder paths and sibling order, not from randomness. You build a spatial memory of where Work is, and it has to stay true.

Crown

The tree grows up and out from the moon. Depth is height, and every area gets its own slice of the circle.

Best for: "where is everything?" The default.

Cone

Robertson's Cone Trees from Xerox PARC (1991): the children of each node hang in a ring below it. Rotating a ring brings a sibling to the front.

Best for: comparing siblings, and very wide nodes.

Galaxy

A force layout in which links pull as well as branches. Nodes that link to each other drift together, even across areas, and that shows connections the tree hides.

Best for: "what is related to this?"

Two more are worth trying later. In Helix, dated nodes such as a journal's 2026 › October › Stardate 2026.10.02 wind up a spiral, one turn per month, so the Captain's Log becomes a timeline you can fly along. In Terraces, the tree is a flat 2.5D landscape tilted 30°: each level is a terrace and folders are plateaus. It suits trackpads and people who don't like free 3D.

Workspace

Tabs and windows still matter in space

Tabs

Each tab is a station

A tab keeps its windows and a saved camera. The dock lists tabs as now, with one pip per window. 1–9 fly between them. Hovering a tab you are not on lights its windows' nodes faintly, so you can see where it is before you go.

Windows in Pages

Each window looks into the space

In Pages, the tab keeps its split layout and every window is its own view into the same space, with its own camera and its own Back / Forward. Zooming flies only the window you are in, and a page open in two windows stays in sync between them.

Windows on the map

Joined to what they show

In the map shapes, a window floats beside its node with a thin line between them. A window whose node is off screen is pinned to the edge, and its line points the way, so every window stays one click away.

Open here

Send a window to a node

Select a body and press ⏎. The focused window moves there, and its line swings over. ⇧⏎ opens a new window there instead. These are openLocation and openLocationInNewPane, as they work today.

Flatten

Back to 2D at any time

Leaving 3D plays Lunamux's entry animation in reverse: the windows fly back into the tab's real split layout. 3D only adds a view. Your layout is never changed by entering it.

Gather

Draw a tab with a lasso

Drag a lasso around a group of bodies to make a new tab with one window per node. It is the quickest way to set up a workspace for "this week's work".

Parking orbit

A shelf for spare windows

This is Lunamux's stash. Windows you want close by but out of sight wait in a ring around the camera, and you can bring one back to dock it.

Further out

Ideas to try

Arrange

Drag a body to reparent it

Grab a body and carry it to another branch. The new parent glows, and dropping runs the same moveRows and folder move as dragging a dot in 2D. One undo puts it back.

Time

Recency glow

Nodes edited today glow warm and cool off over a week. Today's edits leave a faint trail between the bodies you visited, like a comet's tail.

Agents

MCP probes and scopes

Each agent connection's folder scope shows as a soft dome. When an agent edits, a probe flies into the dome and lands on the node. You can see what Claude is touching while it happens.

Untidy

The orphan belt

Folders no bullet references, which the folder contents list shows today, drift as an asteroid belt around their parent. Dragging one into the tree is "Convert to node".

Links

Fly through a pipe

Click a link pipe to travel along it to the other end, with a short warp. It is the 3D version of following a link, and Back flies you back through it.

Search

A sweeping beam

While you type, a beam sweeps out from the selected node, and hits light up as it passes. The scope works as it does in 2D: only this subtree, or the whole vault with in:/.

Places

Pinned positions

Let the user drag a top-level area somewhere and keep it there. Pins are stored as UI settings per vault, never in the vault itself.

Headsets

visionOS and Quest

The same scene in WebXR. The windows become real floating windows, and you write on a keyboard with the docked window in front of you. Of all these ideas, this is where the one rule matters most.

Architecture

How it fits the layers

The rules stay the same. The space is a view of the vault, and its logic lives in commonMain without any 3D imports. Windows are still PaneBackingViewModels, unchanged. The docked editor is the window's own MainScreen, moved in front of the camera.

  • Graph data comes from what the registry already keeps: vaultListingsFlow for folders and files, VaultIndex for link edges, TextIndex for tags and search, linkStatusFlow for broken links, and FoldMemory for what starts open.
  • Layout is pure and testable: a function from the graph, the fold state and the shape to positions, seeded by folder paths. It is unit-tested like FolderContentsTest.
  • Rendering uses three.js, loaded by a dynamic import() into its own webpack chunk, as Excalidraw is, so the app costs nothing until the user opens 3D. Pages are real DOM placed with three's CSS3DRenderer, as Lunamux places its panes. Bodies and pipes use WebGL.
  • Persistence: the camera per tab, the shape and pins live under one persister key, lunarborSpace. No vault format change, so no migration.
  • Demo mode works as is: DemoFileSystem feeds the same listings, so the website demo gets 3D too.

Scale

A real vault has thousands of folders

  • Folding decides detail. A folded body carries its whole subtree inside its ring. The camera unfolds as you approach and folds again as you leave, using the zoom rule of refolding what was left behind.
  • Load only what you approach. Listings are already loaded per folder on demand. Outlines are only read for bodies near the camera.
  • One draw call per kind. Bodies, satellites and dust are instanced meshes, and branches and pipes are one line buffer each.
  • A label budget. About 40 labels at most, chosen by depth, distance and relevance: selection, windows and search hits first.
  • Render only when something changes. The loop stops once the camera and layout settle, so the space uses no power while you write in a docked window.
Plan

Build it in this order

  1. Pages

    The zoom becomes a flight between pages that hang in space. The editor is unchanged, and only the camera is new. This is the cheapest step, and it tells us whether moving through space helps people find their way.

  2. Map

    Step back from the pages into the Crown view of the folder tree, with labels and fly-to. Clicking a body flies to its page.

  3. Workspace in space

    Windows joined to their nodes, tabs as stations, docking to edit at 1:1, and the entry and exit animations.

  4. Connections

    Link pipes, the Galaxy shape, tag colours, search lighting, and search nodes as beacons.

  5. Direct manipulation and atmosphere

    Drag to reparent, lasso to make a tab, pinned areas, agent probes, recency glow, the Helix timeline, WebXR.

Open questions

To decide

  • In Pages, should sibling pages hang next to the current page, so you can move sideways from one to the next? The prototype shows only pages further in.
  • In a narrow window, the child pages are pushed to its edges. Should a narrow window show fewer of them, or hide them until you hover the window's edge?
  • Should Esc fly up one level, as in the prototype, or clear the zoom altogether, as it does in Lunarbor today?
  • Should 3D be a mode for the whole app, as in Lunamux, or a kind of window? A "map window" next to normal windows would be cheaper to try and might be all most people need.
  • Should leaf bullets appear as dust at all, or is a node's size enough? Dust adds life up close but costs draw calls in large outlines.
  • Blocks with children are items too. Should a block be a different body, for example a flat slab, to show that it holds free text?
  • How much Lunamux code can be shared? The CSS3D window and engage code could become a toolkit module that both apps use.
  • Should the camera follow the docked window as it moves between nodes, as in the prototype, or stay still to keep the user oriented?
