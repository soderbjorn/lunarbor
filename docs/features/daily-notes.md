# Daily notes, templates, done

Feature spec moved out of `CLAUDE.md` to keep it small. Keep it current when you change the feature.

## Daily notes

A day is an **ordinary node** at `/Journal/<year>/Week <NN>/<YYYY-MM-DD Weekday>` (LBR-18; no format change, no migration). The rules are pure commonMain (`main/DailyNotes.kt`, tested in `DailyNotesTest`): `CalendarDate` (no date library; the web layer passes the user's **local** date, `localToday()` in `AppShell.kt`), `IsoWeek`; the year is the ISO week-numbering year (2025-12-29 is `2026 › Week 01`), weeks are `Week 01` … `Week 53`, days `2026-10-05 Monday`.

- **Today** (palette "Today", ⌘D — Ctrl-D off the Mac, a rebindable `HotkeyBindings` action `lunarbor.today`; `PaneBackingViewModel.navigateToToday(today)` → `TodayOutcome`): opens the root outline (file history, like a link — so it works from notes and file views), walks `Journal` (a root item matched by `FolderName.nameTextOf`, case-insensitive; a new one goes last at the root) › year › week › day reusing what exists and unfolding each for the pane (`expandForPane`), inserts what is missing **newest first** (a new year first under `Journal`, a week first under its year, a day first under its week) and zooms into the day (zoom history when already on the root outline; morph and page memory as any zoom), caret on its first child. Already on today (zoomed in, or on the day's folder) does nothing.
- **Pending rows** (`Document.insertPendingRows`, `State.pendingRowsGroup`): the prepared items plus an empty placeholder child under the day are on screen in every pane but **never saved** — `Document.savedView` leaves them out of every save and dirty check, so an untouched day writes no folder, outline or stamp. One group per preparation, refcounted across panes (`holdPendingRows` / `releasePendingRows`; another pane's Today on the same day joins it, or `extendPendingRows` when nesting under it). The first edit that changes one of a group's rows — its text (typing, Toggle done, indent), its parent, its place among the pending rows, or deletes it — commits the group (`PaneBackingViewModel.commitTouchedPendingRows` from `recordEdit` → `Document.commitPendingRowsEditedBetween`, comparing the edit's before and after rows; where the caret was does not matter, so an edit of a line elsewhere in the same document — Toggle done on a search-node result, LBR-22 — keeps the day a throwaway), as does a non-pending row nested under one (`settlePendingRows`); from then on the normal save rules make the folders. Leaving (zoom change, file switch, pane close — `cleanupEmptyPlaceholderIfAny` → `releasePendingRowsIfAny`) lets go; the last holder's release removes the rows still pending — day, and the week / year / `Journal` it alone justified. Undo snapshots never restore dropped rows (`replaceContent`); a reload from disk drops pending groups. A breadcrumb up to a dropped item lands on the nearest survivor (`ZoomNavigation.zoomTo`). Unlike `pendingLeafZoomChild` (saved, stripped as a trailing empty bullet), this is the mechanism for anything prepared but not yet the user's (LBR-21's template rows).
- **Previous day / Next day** (LBR-20; palette only, no hotkeys, offered only while the pane is on a journal day or anywhere inside one — `PaneBackingViewModel.journalDayOf`: the active file's decoded folders plus the zoom path, read by `DailyNotes.dayOfTitlePath`: `Journal` › four-digit year › `Week NN` › a `YYYY-MM-DD Weekday` title with a real date and its own weekday, `dateOfDayTitle`). `navigateToAdjacentDay(forward, today)` reads the journal's existing days from disk after `flushAll` (`journalDays`: root › `Journal` › year › week › day items via `DocumentRegistry.nodeItemsOf`, so untouched pending rows never count; anything the privacy mode hides — a hiding tag on the item, or its folder `isPathHidden` — is skipped with its subtree) and steps with `DailyNotes.stepFrom`: the nearest existing day before / after, gaps, weeks and years skipped; none → `TodayOutcome.NO_DAY`, nothing changes. Going forward, today counts whenever it lies after the day and no existing day comes first, and goes through `navigateToToday` itself (prepared, pending). An existing day is opened along its actual title path through the Today command's `openJournalPath(titles, prepare = false)` — same file history / zoom history, morph, page memory and throwaway placeholder child.
- **Daily template** (LBR-21, `main/DailyTemplate.kt`, tested in `DailyTemplateTest`): any node can be the template. Palette "Use as daily template" on a node page other than the root (`PaneBackingViewModel.canUseAsDailyTemplate` — the zoomed item's folder or an open outline's folder, `currentNodeFolder`) makes it the template, replacing an earlier one; on the template's own page the palette offers "Stop using as daily template" instead (`isDailyTemplatePage`, `setDailyTemplate`), and its title wears a small "Daily template" pill (chrome, `MainScreen.appendDailyTemplateLabel`). The template is a setting with no settings UI: its vault folder, `DocumentRegistry.dailyTemplate` (mirrored into `State.dailyTemplateFolder`), persisted per vault under the persister key `lunarborDailyTemplate` (`{ "<vault>": "<folder>" }`, `AppShell.loadDailyTemplate`); `applyPathMoves` re-keys it when the folder moves or is renamed and forgets it when it (or only its outline) goes to the trash; a stored folder without an outline means no template. When Today (or Next day → today) prepares a day that **does not exist yet**, the day's children are a copy of the template's own items with their whole subtrees (`DocumentRegistry.dailyTemplateRows`: open documents flushed first, folder-backed children read from their folders; bullets, blocks, search nodes, nested children; vault links and images written vault-rooted, as copy does, so the day's first save re-bases links for its folder; images are not copied) in place of the empty placeholder (`DailyNotes.preparedRows`), all in the day's one pending group: a **throwaway until the first edit inside the day**, exactly like the placeholder — nothing on disk before it (no folder, `_node.md` or stamps; never "write, then trash"), the first edit makes the day and everything copied real, leaving untouched removes the copy, the day and the week / year it alone justified, and several panes share it until the last one leaves. Days that already exist are never changed; editing the template affects only days prepared later; no `{{date}}` substitution. Not applied (the day gets the empty placeholder) when the privacy mode hides the template node; items inside it that the mode hides are left out of the copy. A search node with no `in:` searches the tree its line is stored in — inside a day, only that day — so templates should say `in:/Journal` or `in:/`; queries are never rewritten. Suggested starter, the open-tasks list that replaces carrying tasks over (LBR-22, LBR-24):

  ```
  - Open tasks {{search: #todo is:open in:/Journal}}
  ```
- **Done** (LBR-24; `data/DoneState.kt`, `main/DoneLayout.kt`, tested in `DoneStateTest` and `DoneTest`): an item whose **whole title** is struck through is done — `~~Buy oat milk~~ #todo` is, `Buy ~~oat~~ milk` is not; tags, a search node's `{{search: …}}` and whitespace at either end don't count (`DoneState.coreRange`); a block's first row decides, a code row never is. Everything under a done item is done too, at any depth and across files. No format change (GFM strikethrough). The rule is pure and works on one line's text: `DoneState.isDoneText` / `withDoneText` (title) and `isDoneRow` / `withDoneRow` / `toggledRow` (a `Document.lines` row: indent, bullet or block marker, list and heading prefixes kept); `isDoneNoteLine` for `.md` note lines (after a list marker / task box; they inherit nothing).
  - **Toggle done** (palette "Toggle done", ⌃↩ on the Mac — Cmd-Enter / Shift-Cmd-Enter leave blocks, Option-Cmd-Enter zooms — Alt-Enter elsewhere; `MainScreen.handleKey`, listed in `lunarborHotkeysSpec`): `PaneBackingViewModel.toggleDone` wraps or unwraps the whole title of the caret's item in `~~`, tags kept outside (strike marks already inside the title are merged into one span), or of every item a multi-row selection touches — all marked unless all already are, then all unmarked. One undoable edit from `Document.delete` / `insertText`; the caret stays on its word. A child done only by inheritance is struck on its own. Not in Markdown mode, file views or read-only pages (`canToggleDone`); privacy-hidden rows and code rows are skipped. A folder-backed item keeps its folder (the folder name is the title's plain text).
  - **Look:** a done item is struck (its Markdown) and dimmed, the rows under it dimmed only (`.lunarbor-row-done`, `PaneBackingViewModel.isRowDone` → `DoneLayout.doneRows`). Search results and search-node rows of done lines are dimmed too (`TextHit.done`, `.lunarbor-hit-done`). The outline view only sees done-ness within the open document; a node whose done ancestor lives in a file above is not dimmed there (the index knows: `TextIndex.isFolderDone`).
  - **Hide done items** (palette "Hide done items" / "Show done items"; `State.hideDone`, `setHideDone`): pane state, persisted with the pane's location (`PaneLocationStore` `hideDone`). Done items on the page and their subtrees are not on screen (`hiddenOnScreenIn` merges `DoneLayout.hiddenRows` into `visibleRowsIn`, `hasChildrenOnScreen` and `ensureVisibleRow`) — counted from the row after the zoom target, so a done page still shows its children. A view filter, not privacy: edits are never refused, and the privacy checks keep using `hiddenRowsIn` alone.
  - **Search:** `is:done` / `is:open` (= `-is:done`) in `SearchQuery` (`Expr.Done`), so pane search and search nodes both have it (`{{search: #todo is:open in:/Journal}}`). `TextIndex` computes each line's done flag from the raw line at index time (the normalized key has lost the `~~`); each outline records its done folder-backed items (`Entry.ownedDone`, like `Entry.owned` for tags), so lines in their folders inherit it; `matches(text, tags, done)`. Every `TextHit` carries `done`.
- **Privacy:** a mode hiding `Journal` or a part of the path (`isTodayHidden`: the root row's tags, then the path's folders via `isPathHidden`; rows re-checked on the way down) returns `HIDDEN` before the pane moves; `AppShell.goToToday` shows a short notice that names neither mode nor tags.
